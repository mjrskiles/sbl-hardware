# sbl-hardware Context

Hardware definitions and bare-metal drivers for Sound Byte Labs.

## Driver Patterns

- **Template on instance:** `Uart<N>`, `I2c<N>` — instance index selects registers
- **Header-only:** Templates, constexpr, inline. No .cpp except IRQ handlers
- **No vendor HAL:** Direct register access via `sbl::hw::reg::periph::*`
- **Static allocation only:** Buffers declared static in driver headers
- **IRQ handler files are direct app sources** (not in a static lib): `dma_irq.cpp`, `uart_irq.cpp`, etc.

## Register Files

Generated by cecrops from SVD; change them by regenerating. The hand-written exceptions are listed
under `manual` in the MCU's `cecrops.json`.

Regenerate:
```bash
python -m cecrops generate sbl-hardware/mcu/arm/stm32h750
```

Validate (read-only — checks the SVD against `cecrops-anchors.json`):
```bash
python -m cecrops validate sbl-hardware/mcu/arm/stm32h750
```

`generate --validate --strict` also validates but **rewrites every output header**
(timestamp line changes even when content doesn't). Only use it when you mean to
regenerate. Anchors exist only for peripherals listed in `cecrops-anchors.json`;
add an anchor whenever code starts depending on a new peripheral's register offset.

## Manifests (ADR-010)

**MCU (`mcu.json`):** Pin definitions with all alternate functions (gpio, uart, spi, adc, etc.). Declares timing capability.

**Main module (`hardware.json`):** Has `"main": true` and a `system` section (MCU reference + boot config). Claims board-level peripherals (codec, UART). Exposes remaining pins.

**Attached module (`hardware.json`):** Claims pins from a parent module. Declares components (knobs, buttons, LEDs). Portable — no `attaches_to` in the manifest.

**Device (`device.json`):** Composition authority. Names a main module + attached modules. Specifies attachment topology. App-agnostic.

**Component (`component.json` or `*.json`):** Reusable definitions for front-panel components (pot, button) and ICs (PCM3060 codec with bundled driver). Referenced via `ref` in module manifests.

Pin resolution: device specifies topology → attached module claims pin by name + function → main module maps to MCU pin → MCU provides port/pin/AF. Conflicts detected automatically.

## Build Notes

- New STM32H750 driver headers go in the explicit list in `mcu/arm/stm32h750/CMakeLists.txt`;
  CMake re-runs configure when the list changes
- STM32H7 kernel clocks: every peripheral needs explicit clock mux selection
- Compile flags: `-O2 -g` (not `-Os`) for Cortex-M7
