# sbl-hardware Context

Hardware definitions and bare-metal drivers for Sound Byte Labs.

## Structure

```
sbl-hardware/
├── mcu/arm/              # MCU definitions
│   ├── rp2040/            # Cortex-M0+ (Pico SDK drivers)
│   ├── rp2350/            # Cortex-M33 (Pico SDK drivers)
│   └── stm32h750/         # Cortex-M7 (bare-metal, SVD registers)
│       ├── driver/        # Hand-written drivers (gpio, uart, sai, adc, dma, i2c, etc.)
│       ├── reg/           # cecrops-generated register headers — DO NOT EDIT
│       ├── mcu.json       # Pin definitions with alternate functions
│       ├── cecrops.json   # SVD generation config
│       ├── startup.cpp    # Reset handler, vector table, .init_array
│       └── stm32h750.ld   # Linker script
├── mainboards/            # Board manifests (daisy-seed, pico, pico-2, daisy-patch-sm)
└── modules/               # Extension module manifests (daisy-pod, patch-init)
```

## Driver Patterns

- **Template on instance:** `Uart<N>`, `I2c<N>` — instance index selects registers
- **Header-only:** Templates, constexpr, inline. No .cpp except IRQ handlers
- **No vendor HAL:** Direct register access via `sbl::hw::reg::periph::*`
- **Static allocation only:** Buffers declared static in driver headers
- **IRQ files must be direct app sources** (not static lib): `dma_irq.cpp`, `uart_irq.cpp`, etc.

## Register Files

Generated by cecrops from SVD. **Never edit by hand.**

Regenerate:
```bash
python -m cecrops generate sbl-hardware/mcu/arm/stm32h750
```

Validate:
```bash
python -m cecrops generate sbl-hardware/mcu/arm/stm32h750 --validate --strict
```

## Manifests

**MCU (`mcu.json`):** Pin definitions with all alternate functions (gpio, uart, spi, adc, etc.)

**Mainboard (`hardware.json`):** Exposes MCU pins to modules. References an MCU.

**Module (`hardware.json`):** Claims pins from a mainboard via `attaches_to`. Defines components (knobs, buttons, LEDs).

Pin resolution: module claims pin by name + function -> mainboard maps to MCU pin -> MCU provides port/pin/AF. Conflicts detected automatically.

## Build Notes

- After adding new driver headers: `cmake --preset <target> --fresh`
- STM32H7 kernel clocks: every peripheral needs explicit clock mux selection
- Compile flags: `-O2 -g` (not `-Os`) for Cortex-M7
